1. PROJECT OVERVIEW

Q-Rescue AI is a disaster emergency response decision-support system for
Sheffield. It simulates disaster scenarios and compares three approaches to
allocating ambulances and rescue resources:

  - Simulated      : rule-based calculation from user inputs
  - AI Predicted   : XGBoost model forecasts (Member 5)
  - Quantum Optimised : QUBO/QAOA quantum solver (Member 1)

Member 3 owns the entire Streamlit frontend dashboard that ties all outputs
together visually.

  - get_active_simulation_results(): priority chain:

4. MEMBER 5 AI MODEL INTEGRATION

The prediction layer supports two modes:

  MODE A — Heuristic (default, always works standalone)
    predict_outcome(simulation) computes a deterministic forecast from the
    scenario inputs using population pressure and resource gap calculations.
    A warning banner is shown on page 7.

  MODE B — Real XGBoost output (live integration)
    When Member 5's pipeline runs build_dashboard_payload() and stores the
    result in Streamlit session state, page 7 automatically switches to
    showing real model output with a green success banner.

    To activate MODE B, Member 5's pipeline must store:
      st.session_state["ai_dashboard_payload"] = dashboard_payload

    The dashboard_payload is a DashboardPredictionPayload dict produced by:
      src/q_rescue/ai/predictor.build_dashboard_payload(predictions, scenario)

Integration adapter (frontend/prediction.py):

  predict_outcome_from_payload(payload, simulation)
    Converts DashboardPredictionPayload fields to the prediction dict shape:
    - dominant_severity -> forecast_severity (via _M5_SEVERITY_TO_SCORE map)
    - mean_resource_demand -> ambulance/rescue team demand
    - per-incident flood_severity_label + confidence -> risk_areas DataFrame
    - Returns dict with "_source": "xgboost"

  get_prediction(simulation)
    Checks st.session_state["ai_dashboard_payload"] first.
    Falls back to predict_outcome() if absent or empty.
    Returns dict with "_source": "heuristic" or "xgboost"

  Severity label to score mapping:
    Low      -> 2.5
    Moderate -> 5.0
    High     -> 7.5
    Severe   -> 10.0

5. BUG FIXES APPLIED

  FIX 1 — PyArrow mixed-type serialization error
  File   : frontend/ui_theme.py — render_table()
  File   : frontend/pages/1_Disaster_Input.py — Metric Value column
  File   : frontend/pages/2_Results_Dashboard.py — Metric Value column
  Error  : pyarrow.lib.ArrowTypeError: Expected bytes, got a 'int' object
           Conversion failed for column Metric Value with type object
  Cause  : DataFrames with mixed int/string columns cannot be serialized
           by PyArrow (used internally by Streamlit's st.dataframe).
  Fix    : render_table() now calls .astype(str) before .to_html() so all
           columns are uniform string type before rendering.
           Raw int values in Metric Value columns cast to str() explicitly.

  FIX 2 — Deprecated use_container_width parameter
  File   : frontend/pages/1_Disaster_Input.py
  Change : use_container_width=True replaced with width="stretch" in
           st.dataframe() call as required by newer Streamlit versions.
